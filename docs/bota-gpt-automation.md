# Bota për Kosovën: international portrayal and Albanian reading

Confirmed scope: daily Hermes VPS job, OpenAI Codex subscription, GPT-6 Luna, xhigh; international articles materially discussing the Republic of Kosovo; positive/negative/neutral **portrayal**, not the event's desirability. A factual report of sanctions is neutral unless the article itself frames Kosovo unfavorably. Attributed hostility belongs to the speaker, not automatically to the publisher. Each published article has its complete extracted text translated paragraph by paragraph, source attribution, original link, and an Albanian explanation of its rating. Existing page layouts and unrelated jobs are preserved.

`tools/bota_gpt.py` reuses multilingual RSS discovery and publisher-ownership rules without calling Groq or Gemini. An additional global search captures international sources outside the existing regional feeds. Direct publisher RSS feeds and previously resolved fresh publisher URLs provide an independent path when Google redirect decoding is unavailable. Original HTTPS publisher pages are resolved and extracted using trafilatura. Private hosts, restricted/truncated text, missing full bodies, local place names, non-journalism and domestic sources are excluded. Candidates are balanced across locales before extraction and countries before GPT processing. The target is 50-100 unique new articles per Kosovo calendar day. Direct-link Bing News RSS searches across 56 markets supplement publisher feeds and Google discovery. Up to 800 country-balanced candidate pages are inspected and 300 new sources considered per pass; four concurrent subscription streams stop at the remaining daily capacity or the 50-minute editorial budget. Every accepted translation is durably saved before publication. At most 100 new articles are published daily; unavailable sources are never replaced with fabricated translations or headline-only ratings.

The worker checks the live Codex model catalog and exact outgoing and returned model/reasoning settings. It uses Hermes's authenticated `openai-codex` runtime and Codex Responses transport. No alternate model/provider is permitted. Structured responses must preserve paragraph count, reasonable translation length, and numeric facts. Every charged rating has a short original evidence span. Publisher text is untrusted data, never instructions. Actual model, reasoning, response IDs and usage are retained in a private run receipt.

Apply `supabase/migrations/0080_bota_gpt_coverage.sql` and `0081_bota_daily_topups.sql` to the application's production database. Only the service role can read/write these tables directly. Authenticated `/api/automation/bota/daily` appends verified daily batches atomically through `publish_bota_coverage_v2`, preserving earlier article bodies and ratings. A shared transaction lock caps cumulative unique articles at 100 and retries return only actually inserted IDs; public `/api/bota` exposes the derived seven-day snapshot. `/bota-per-kosoven/artikull/<sha256-of-source-url>` renders stored Albanian paragraphs safely as text. Source bodies and credentials are not returned to readers. Old version-4 event ratings never mix with the new version-5 portrayal ratings. The old Groq GitHub schedule is retired. **Daily publication does not deploy or commit application files.**

VPS dependencies: the existing Hermes environment plus feedparser, requests, beautifulsoup4, googlenewsdecoder, groq (legacy discovery-module import only), and trafilatura. No Groq API key is used. Publishing reads CRON_SECRET or TREGU_AUTOMATION_SECRET from the environment or the existing protected automation env file; credentials never appear in logs.

Dedicated clean source checkout: `/opt/data/workspaces/383lajme-bota-main`. Cron entry: `/opt/data/scripts/run-bota-gpt.py`. Run at 07:23, 11:23, 15:23 and 19:23 Kosovo time (`23 7,11,15,19 * * *`) to top up the daily publication as news appears. Hermes's configured Europe/Warsaw timezone has the same DST offsets as Europe/Belgrade. The entry locks concurrent runs, fetches main and fast-forwards the dedicated clean checkout. No branch reset, forced push or deployment command is used. A one-hour runtime cap prevents a stuck model call from running indefinitely.

Before activation: unit tests, production build, clean GitHub push, exact Railway SHA verification, database migration, a real model smoke test, publication/readback test, desktop/mobile reader checks, and saved Hermes job/next-run verification. Retain failures honestly: never report a daily publication when extraction, model provenance, persistence or public readback failed.

The worker stops starting new GPT calls after 50 minutes, leaving time to publish verified work before the scheduler's one-hour cap. Each completed translation is saved in a private atomic pending packet. A same-day retry resumes publication and reader verification from that packet without repeating GPT calls. HTTP failures preserve the packet; successful public readback removes it. The receipt records failed and deferred candidates explicitly.

Before adding an article to a batch, the worker runs the exact Node validator imported by the publishing API. A malformed individual result is excluded rather than rejecting all translated articles. Publishing errors log the HTTP status and bounded validation message; credentials and article bodies remain private.

Email-enabled Hermes entry: `/opt/data/scripts/run-bota-gpt-email.py`, with `bota_email_report.py` beside it. It calls the existing clean-source entry, verifies the current public version-5 batch and every today's Albanian reader, and sends each run's outcome to the confirmed owner `lindsylqa@gmail.com` through the existing Gmail STARTTLS credentials in `/opt/data/.env`. Success, already-published verification, fresh dry-run tests, skips, and failures have distinct subjects. A fresh test never claims a new publication; a saved-packet retry never claims new GPT calls. SMTP failures preserve private queued reports and mark the job as failed; subsequent runs retry up to five older reports before their own email. `/opt/data/automation/bota/last-notification.json` records SMTP acceptance and the actual verified outcome. Email credentials never appear in logs or the repository. Install these job scripts on the persistent Hermes volume and update the existing job's script; this notification-only change does not require a website deployment.
