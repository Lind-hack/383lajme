# Plan: Article page overhaul + dosje rebuild
_Locked via claudex-loop — by Claude + Lind, 2026-10-21. Branch `feat/article-page-overhaul` off `origin/main` (3ce6a2f1)._

## Goal
Make `/article/[slug]` calm, clear and easy to follow: every block on the page is either the story, real context for the story, or a genuinely related next read. Fix the Tregu gap bug, remove fake/noisy elements, make "related" actually related, and replace the unsourced dosje with an automatically rebuilt, fact-checked history of what led up to the story. The dosje runs once a day on GPT-6 Luna (Codex subscription, VPS) and auto-publishes only what passes deterministic verification; Lind gets one clear daily email listing exactly what went live, where, and with what.

### B. Dosje pipeline (VPS, GPT-6 Luna)
11. **Wipe** (Lind's explicit choice: all three layers), sequenced so readers are never left with a broken read path:
    1. Backup: `pg_dump --data-only` of every `dosje_*` table to `/opt/383-supabase/backups/dosje-<date>.sql` on the VPS, plus a JSON copy locally (not committed). **Restore-test** before deleting anything: in one BEGIN…ROLLBACK, `create schema dosje_restore_test`, `create table dosje_restore_test.<t> (like public.<t> including all)` for each table, load a copy of the dump rewritten with `sed 's/public\.dosje_/dosje_restore_test.dosje_/g'` (pg_dump schema-qualifies every name, so `search_path` alone would hit the live tables), and compare row counts with the live tables. Confirm `/opt/383-supabase/backups/` exists (create it if not).
    2. Delete all DB rows in FK order in one transaction: `dosje_media`, `dosje_citations`, `dosje_milestones`, `dosje_article_topics`, `dosje_research_runs`, `dosje_topics`. (Readers barely notice: today's visible dosje is the file fallback.)
    3. Run the backfill (step 17) and verify new DB dossiers render.
    4. **Then** ship the code removal of the file layer: the `TOPICS` timelines/vocabulary in `lib/topics.mjs` and the fallback in `lib/dosje-entries.ts` (`dosjeFor` returns only DB dossiers; no "pa burime" state). Update every importer: `lib/topics.test.mjs`, `lib/topics-images.test.mjs`, `app/dosje/page.tsx` (`articlesForTopic`), `app/dosje/[slug]/page.tsx`, research route `topicBySlug/researchGroups`, `subjects/route.ts:75`, `media/route.ts:151`, `lib/dosje-feed.mjs`, `listAllDosjeTopics` → sitemap. Keep pure matching code (`lib/dosje-match.mjs`).
    Lind is told before step 2 and before step 4.
12. **Schema** — migration `0115_dosje_daily.sql` (next free number; re-check `git ls-tree origin/main supabase/migrations/` at ship): add `match_groups jsonb`, `context text[]`, `research_groups jsonb`, `primer text`, `created_by text` to `dosje_topics`, so DB topics carry the same event fingerprints the file topics had (without them `scoreTopic` falls back to one group per anchor and a lone "Kurti" clears `MIN_TOPIC_SCORE`); `dosjeUniverse` reads them from the row. Add `model text` to `dosje_milestones`. Add RPC `dosje_publish_bundle(p jsonb)` (SECURITY DEFINER, service role only): in one transaction upserts the topic, inserts each milestone as `draft`, inserts its citations, then updates it to `approved` so `dosje_require_sources()` (BEFORE INSERT OR UPDATE, counts live citations) judges the complete row; each moment in its own savepoint so one refusal does not sink the others; dedupes on existing unique `(topic_slug, dedupe_key)`; returns per-moment outcome (`approved` / `refused: <reason>` / `duplicate`). Refusals are caught by SQLSTATE `P0001` raised by `dosje_require_sources` and unique-violation `23505` only; any other error aborts the whole call (a real bug must never be reported as a refusal). A new topic is inserted as `draft`; an existing topic's `ON CONFLICT DO UPDATE` refreshes vocabulary/blurb but **never touches `status`** (so a re-run can never hide a live dossier). Status is set to `approved` only in the branch where **at least one of its moments ended `approved`** (public read requires an approved topic, 0053) — the receipt only lists a moment as published when both are true. `set search_path = public`; `revoke all … from public, anon, authenticated; grant execute … to service_role` (0051/0057 pattern). Tested with BEGIN…ROLLBACK on prod first.
13. **Worker**: `scripts/run-dosje-daily.mjs` on the VPS, modelled on `scripts/run-tregu-daily-drafts.mjs` — calls `hermes chat --provider openai-codex --model gpt-6-luna` (Codex OAuth, no API key). **Luna shares one usage limit with the hourly news writer** (verified 2026-10-20 22:50 UTC: `HTTP 429: The usage limit has been reached`). Lind's decision: Luna first; on a 429 the run switches to free Gemini for the rest of that run, under identical verification, and the email records which model wrote each moment. Do **not** reuse `requestDailyCodex` as-is (`lib/tregu-daily-codex.mjs` retries any provider throw up to 3×): a wrapper detects `429`/"usage limit" in Hermes output and throws a distinct `LunaLimitError` that breaks out immediately. Gemini path: the worker is plain `.mjs` and cannot import `lib/llm.ts`, so it calls the Gemini REST `generateContent` endpoint directly (JSON response mode, key from the VPS env), Gemini only — no Groq. The deadline check ("no new model call after 06:40") lives **inside** the wrapper before every attempt, including retries for malformed JSON. Timing: starts 05:00 Europe/Belgrade, **hard stop 06:50** (no new model call after 06:40) so it never overlaps the other Luna callers: news writer `383-production` (hourly 07:00–23:00 Warsaw), Tregu daily drafts (07:20 Belgrade, up to ~42 min), Bota daily (07:23 Warsaw, up to ~3h50). Concurrency: one `flock` shared by daily and backfill runs; per-subject claims reuse `dosje_next_subject` / `dosje_sweep_stale_claims` (0055/0059). systemd `383-dosje-daily.service` + `.timer`, 05:00 Europe/Belgrade, lock against concurrent runs, runtime cap. Installed from a committed release like the other VPS jobs.
14. **Daily run, in order:**
    1. **Discover topics** (code): last 21 days of articles grouped by shared entities + title stems; a group qualifies at ≥3 articles over ≥2 days (existing `isStandingSubject` rule).
    2. **Propose** (Luna): title, one-line blurb, anchors/signals/excludes **and matchGroups** (event fingerprints: term sets that must all appear) + context terms — from those articles only.
    3. **Topic check** (code, "a little less strict" per Lind), run with the real `matchTopic` on the proposed groups: matches ≥2 of its own group's articles; matches ≤20% of unrelated recent articles; no overlap with an existing topic (≤30% shared matched articles). Max 3 new topics/day (backfill: up to 20).
    4. **Research** up to 5 subjects/day. Evidence via existing `gatherEvidence` (Wikipedia for leads only, tiered publishers, Wayback fallback). Prompt refocused on **history: what happened before** — the causes, key earlier events and agreements that explain today's story — plus a 2–3 sentence "Në pak fjalë" primer. Each moment: date, title, 2–3 short sentences, one-line "Pse ka rëndësi". Up to 6 moments per subject.
    5. **Verify** (code, unchanged strictness for facts): `validateMilestoneDraft` — ≥2 distinct publishers, every sentence/number backed by a verbatim quote from a fetched source, date in the past, no tertiary-only sourcing. Primer held to the same rule.
    6. **Publish** via new route `POST /api/automation/dosje/publish`. Auth: `Authorization: Bearer` only, constant-time compare (not the `?secret=` / `===` pattern in the existing dosje routes). The worker is untrusted input: the route **re-fetches every citation URL itself** (`fetchSource` + `isFetchableCitationUrl`, private addresses blocked), sets `http_status`/`fetched_at` from its own fetch (Wayback-only text is recorded as such, not as a live 200), **derives `publisher` from the URL itself with `publisherOf(url)` (`lib/dosje-sources.mjs`) and ignores the worker's publisher field** (so two URLs on one host can never count as two publishers), re-runs `validateMilestoneDraft` against the text it fetched, then calls `dosje_publish_bundle`. Afterwards it `revalidatePath`s `/dosje/<slug>`, `/dosje`, and every affected `/article/<slug>` so "now showing on" is true. Returns the RPC's per-moment receipt — the email reports only what the DB actually approved.
    7. **Media**: videos only from the existing channel allowlist (`lib/dosje-video.mjs`), YouTube liveness checked; photos only Commons/CC0/PD/CC BY(-SA) with named creator + rights URL (same policy as `docs/news-copyright-audit.md`); otherwise no photo. Auto-approved when they pass.
    8. **Map articles** to topics (existing subjects logic, folded into this run, before research so `dosje_next_subject` sees today's mapping).
15. **Retire** the 9×/day `dosje-subjects.yml` (+ media job) and `dosje-research.yml` GitHub schedules; keep `dosje-reverify.yml` weekly (link-rot demotion stays).
16. **Email** (one per day, from the VPS via the existing Gmail credentials): subject "383 Dosje · <date> — N momente të reja në M dosje" (or "asgjë e re sot"). Sections: (1) Published — per dosje: new/changed moments with date, title, text, sources (publisher + URL), photo + licence, video title + channel; (2) Articles where each dosje now appears (linked), including articles that moved between dossiers because a topic's vocabulary was refreshed; (3) Didn't make it — subject + one-line reason; (4) Run health — Luna calls, timings, errors. HTML + plain text. Replaces `scripts/dosje_cron_report.py` raw-JSON emails (~20/day).
17. **Backfill**: after the DB wipe (11.2), manual runs with backfill caps (up to 20 topics) inside the 00:00–06:50 window (the news writer's last run fires 23:00 Warsaw and can run up to ~50 turns); before its first model call the backfill also checks that no `383-production.service` is active (`systemctl is-active`) and waits/aborts if one is, over one or more nights as Luna allows (Gemini on 429). Same lock as the daily run.

## Key decisions & tradeoffs
- **Auto-publish** verified moments and topics (Lind, Q1). Trust rests on the deterministic validators + DB trigger, not on a human queue. The daily email is the oversight.
- **Wipe everything incl. topics** (Lind, Q2) → requires new automatic topic discovery (Q4). Risk: loose topics attach the wrong dosje; mitigated by the topic check and the ≥20% false-match cap.
- **Topic check relaxed** (anchor in ≥2 articles, ≤20% false matches) per Lind; **fact verification not relaxed**.
- **GPT-6 Luna on the VPS, Gemini on 429** (Lind). Mirrors existing Tregu/Bota/news workers. The app keeps a validating publish route rather than letting the worker write the DB directly.
- **Review by a fresh Claude agent, not Codex** (Lind): local Codex rejects GPT-6 models on this ChatGPT login and reports the workspace out of credits for 5.6 models.
- **Related scoring in code, not an embedding service** — no new infra; reuses `lib/entities.mjs` / `lib/front-page.mjs`.
- Lajmet e fundit/Më shumë nga require images → some stories never appear there; accepted.

## Risks / open questions
- Luna subscription capacity shared with the hourly news worker (07:00–23:00) — the 05:00 slot avoids overlap; backfill must also avoid 07:00–23:00 or be throttled.
- A dosje topic matching on a single common name (e.g. "Kurti") would attach to most Kosovo politics stories — the false-match cap must be measured on real data before enabling auto-publish.
- After the wipe, articles show no dosje until the backfill lands.
- Server-side market matching on a 2h-revalidated page means the Tregu card can show a market that closed since render — client should hide a closed market.
