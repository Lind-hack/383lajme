# Appearance and account navigation

The profile settings and the menu's lower appearance section share the same accessible dark-mode switch. The choice is saved per device in `383-theme` local storage and the `383_theme` cookie; it is not an account-wide or cross-device preference. The small bootstrap script applies it before hydration, with the cookie as fallback when local storage is unavailable. Changes update the browser theme color and other open tabs.

Neutral surface, ink, muted and border tokens have light-mode fallbacks in the existing public stylesheets. The dark palette changes those tokens, not images or semantic market/category accents. `app/site-theme.css` also covers older inline React styles (both compact server HTML and browser-normalized styles) and neutral Tailwind utilities. New UI should use the theme tokens directly rather than add hardcoded neutral inline colors.

Account UI no longer awaits `getUser()` before rendering: signed-out links are present in the server HTML, and the browser's local session supplies the signed-in display. Protected server routes still verify the user. A valid session can replace the initial links after hydration; no network response gates the initial navigation. Scrolled desktop headers put account access in the drawer, and the menu account section is outside its content scroll area, above categories. Language, search and Pyet Dardanin share one persistent control row. When the desktop hamburger replaces the account links, the shared controls glide together into the freed space and finish beside the hamburger. Category links retain a softer orange gradient with a slower sheen. The drawer omits the tutorial and location tag; its borderless appearance switch follows the menu sections.

Article card gradients use theme surface variables directly. Personal-feed palettes and Tregu search fields switch their surfaces and text together, including accent backgrounds and selected/inverse states. Photographs and dark photo overlays keep their original colours.

The desktop account controls and destination links fade out over the existing 200ms ease-out token while the hamburger fades in within its fixed slot. Scrolling back reverses the CSS transitions from their current progress. Hidden controls are inert; visibility changes after the exit fade. Reduced-motion users switch immediately, and mobile keeps its hamburger visible from the first render. The language/search/Dardani/Tregu cluster moves as one unit with the same 200ms transform transition, keeping its internal order and spacing. Mobile does not shift the cluster; reduced-motion users get the compact final position immediately.
